# Planning 视觉刷新设计

## 目标

将现有任务时间轴统一为产品名 `Planning`，把首屏做成轻松可持续使用的家庭生活计划：打开应用即可看到跨月份的整体安排、任务所属泳道、自动状态和当前进度。视觉上沿用已确认的 `Ink / Cobalt` 冷白方向，但降低办公感，加入柔和、亲近的生活气质，不使用“主线”作为产品或用户界面文案。

## 已确认的视觉方向

- 背景：冷白与极浅灰蓝，用于区分页面、工具栏和时间轴表面。
- 文字：深墨色作为主要文字，蓝灰色作为次要说明；字重只使用常规和中等。
- 强调：钴蓝用于主要按钮、当前时间线和选中态；任务条可按生活领域使用低饱和蓝、薄荷绿、暖杏色，不使用大面积渐变。
- 辅助：低饱和青绿表示持续事项，浅蓝灰表示指标或未开始事项，红色只表示逾期。
- 边界：细描边、低圆角（不超过 8px）、轻阴影只用于弹窗和真正需要分层的工具面板。
- 气质：信息一眼可扫，但留白、圆角和颜色更轻松，像家庭共享的生活安排，而不是项目管理后台或营销页。
- 圆角：常规面板和任务条使用 8px 以内的柔和圆角；不做厚重阴影和堆叠卡片。
- 语气：按钮和状态文案简短、自然，优先使用“新增事项”“今天”“已同步”等生活化表达，避免“项目、里程碑、交付”等办公术语。

## 信息架构

### 首屏生活时间轴

1. 顶部工具栏：`Planning` 品牌、当前日期、回到今天、新增事项；品牌旁可用很小的家庭生活副标识，但不再加入口号或说明段落。
2. 视图工具栏：时间范围、旬/月/年粒度、导入/导出、同步状态。
3. 甘特大盘：左侧泳道名称固定，右侧时间轴可横向滚动；默认显示覆盖所有事项的时间范围，打开时自动定位到今天。
4. 底部图例：未开始、进行中、持续、已逾期、已完成，以及“数据范围随事项自动延伸”。

首屏不再额外堆叠统计卡片、说明卡片或重复标题；甘特图本身就是主视图。列表视图只作为切换后的辅助视图，不改变默认入口。顶部可以保留一行轻量的“接下来”提示，但不能把甘特图挤出首屏。

### 任务与泳道

- 泳道按家庭成员和生活领域分组，当前数据中的 `王` 任务保持可识别；分组名使用“王”“共同安排”“生活指标”等自然表达。
- 任务标题保留用户已有内容，例如雅思考试、学会游泳、三亚行程、找工作机会、看房、购买钻戒、体重控制。
- 任务条展示标题；空间不足时截断，悬停或点击进入编辑，不改变时间轴尺寸。
- 单日任务以稳定宽度的短条显示；无结束日期的任务显示为持续条，并在数据模型中继续保持开放结束日期。

## 状态与时间行为

- 状态由当前日期、起止日期和完成标记自动推导，用户不需要手工切换“进行中”。
- `未开始`：当前日期早于开始日期。
- `进行中`：当前日期位于起止日期之间，且未完成。
- `持续`：无结束日期且已开始，或被标记为长期持续。
- `已逾期`：结束日期已过且未完成。
- `已完成`：任务完成标记优先级最高。
- 今天线使用细钴蓝线和小型日期标签，避免遮挡任务标题。
- 旬/月/年切换只改变时间轴刻度和列宽，不改变任务数据；任务较多时维持左侧泳道和标题的可读性。

## 交互边界

- `新增事项` 打开任务表单，默认日期为今天；从时间轴空白处新增时使用点击位置日期。
- 点击任务条编辑；拖动或前后移动任务时同时更新起止日期，状态重新计算。
- 导入/导出继续使用 JSON 备份；导出文件名统一为 `planning-YYYY-MM-DD.json`。
- 同步状态保留 `仅本机 / 连接中 / 已同步 / 离线 / 同步异常`，用图标和短文字表达，不使用大提示面板占据首屏。
- 登录、同步异常等复杂操作在弹窗内完成，弹窗保持冷白面板、清晰层级和明确关闭按钮。

## 响应式规则

- 桌面端优先展示完整时间轴，左侧泳道宽度稳定，右侧时间区域可横向滚动。
- 手机端保持“大盘”语义：工具栏分两行，时间轴以较窄列呈现并允许横向拖动；泳道名称固定在可视区域左侧。
- 所有按钮和输入控件的文字必须在父容器内完整显示；图标按钮提供 `aria-label` 和悬停提示。
- 不使用基于视口宽度缩放字体；通过换行、滚动和稳定尺寸处理窄屏。

## 命名与资源

- 用户可见产品名、页面标题、PWA `name`、PWA `short_name`、README 标题统一为 `Planning`。
- 用户可见文案中移除“主线”；任务内容中的自然语言不做无关改写。
- 内部存储键可以继续读取既有 `mainline.*` 数据以保证升级不丢数据；新写入可使用兼容别名，但不把内部键暴露到界面。
- 图标继续使用现有 Lucide 图标体系；不新增手绘 SVG 装饰。

## 验收标准

1. 首屏一眼能看到跨月份甘特大盘，不需要先切到列表或逐行打开任务。
2. 桌面端和手机端均能创建、编辑、移动、导入、导出和查看同步状态。
3. 日期变化后，任务状态无需手工更新即可正确变化；完成任务始终显示为已完成。
4. 产品名和文件名统一为 `Planning`，界面不出现“主线”字样。
5. 视觉符合冷白、墨色、钴蓝的 `Ink / Cobalt` 方向，低圆角、无渐变背景、无装饰性大色块。
6. `npm test`、`npm run lint`、`npm run build` 通过，且 GitHub Pages 的 `/planning/` 构建路径不破坏根路径部署。

## 范围外

- 不改变 Supabase 数据表结构、认证方式或任务字段语义。
- 不新增复杂筛选、统计分析、多人协作或通知系统。
- 不在本轮重新设计任务数据内容；仅统一显示名和导出文件名。
